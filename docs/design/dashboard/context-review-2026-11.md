## Implementation decisions

- Settings search now includes the API's explanation of a setting's effect, increasing/decreasing it and cautions. It does not search changing readbacks or actor names, so live polling cannot move a row out from under an editor. A control desk surfaces manual holds and the API's waiting/held/unconfirmed states, with a complete pending-changes filter. It does not interpret an absence of pending changes as healthy greenhouse conditions.
- Schedules now distinguish enabled routine rules from sensor-fault backup windows. The next routine start is taken only from a future planned occurrence on the selected local day with an enabled non-backup rule. It is labelled as planned and subject to controller/line checks. Disabled, blocked, historical and conditional occurrences never masquerade as the next routine watering.
- The climate story now displays temperature and VPD grades separately. Each grades only finite measured points with a band and reports incomplete grading. Missing data is not counted as success; the empty explanation no longer falsely attributes every missing grade to an absent band. Existing excursion links and bounds remain intact.
- Equipment moves the reported controller reasons ahead of the actuator list. The existing Now link to `/equipment#why` now has an explicit target; the diagnostic story and the equipment list share the same API read.
- Now presents the measured temperature and its freshness before the AI narrative. The desktop temperature is less oversized, retaining room for the bands and nearby actions. Phone safety geometry passed responsive browser checks and visual review.

The broad UI source head passed all nine required checks, including 1,556 unit tests and 581 browser tests. The sections below preserve the review findings and intermediate validation history.

### Historical context and retention decisions

The existing 90% Statistics line is explicitly part of the dashboard design (`design-system.md` and `screens.md`), not a newly discovered controller target. Keep its reference geometry and identify its scope. Existing full-day means exclude today; today remains dashed, and missing grades are hatched. The lighting history now explains the actual qualification rule next to the daily table rather than requiring the operator to infer that outdoor lux or an energized light can qualify a minute. DLI remains unavailable rather than estimated from outdoor measurements.

Planting history previously waited for both active and ended data indefinitely when just one request failed. It now displays available records, an incomplete/stale warning and Retry, with active/ended counts explicitly limited to the displayed results. A browser regression covers this failure without any record write. Map and lifecycle controls retain their persisted positions, selection semantics and conflict safeguards.

Water's existing physical-line grouping, clean/fertilized variants, unwired labels, VPD reserve and cap labels already answer the practical control questions. Keep those instead of adding duplicate summaries. Its history already separates irrigation and climate purpose, states narrower meter/run windows, bounds run enumeration and links outcomes back to graphs. Zones retain their own-probe gaps and explicit fallback provenance; the center has no dedicated probe. Band editing already exposes current versus draft, controller night bias, empirical achievable night range, findings and all changed anchors; preserve this context and the advanced disclosure.

Schedule editing now previews the rule in words, including ownership and conditional execution. Saved-but-disabled rules are labelled as such. The existing cap, conflict, prewet/flush and program-confirmation checks remain authoritative. Native CI and reviewed screenshots confirm this preview and its retained guards.

The visual collection now covers primary and secondary routes, schedule and setting drawers, and the band editor at desktop, tablet and phone widths. These are review artifacts, not screenshot assertions of correctness. Existing behavioral suites still govern role, confirmation, keyboard, stale-read and emergency-control behavior. Native CI uses the existing `ci-runners/verdify-platform-ci-dashboard` ARC set (bounded job resources and runner-slot admission), not local builds.
