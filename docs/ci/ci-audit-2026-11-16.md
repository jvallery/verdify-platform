## 2. Answers

**Q1. Wall time.** Uncontended, the critical path is `trusted-precheck` -> `path-impact`
-> `validate-pure-logic-2` (13.4 run) -> aggregate `validate`: median finish 17.7.
Contended, each of those four serial stages waits for a runner (p90 queue 8 to 16 min
per stage, and 12 to 22 min for the 5-second aggregates on the tools set, which sit
behind other runs' 8-minute shards). So under load, wall time is roughly
3-4 x queue + 14 min. The tools set is the hot spot: 16 pods per run on 6 slots.

**Q2. Repeated setup.** Every validate part builds a venv and pip-installs the same
extras (71 s, 4 x per run). Every tools-set Python job runs `uv sync` plus
`uv pip install -r ingestor/requirements-image.txt` (platform-static, platform-tests,
4 campaign-qualification shards). `ci/validate.Dockerfile` (the `verdify-ci-validate`
image) exists but is not the job image of the `verdify-platform-ci` set and is not in
`build.yml`; baking the deps there removes the 71 s per part. firmware-logic gunzips the
replay corpus that containment-firmware also gunzips.

**Q3. Path impact today.** It decides only three things: `dashboard` (dashboard-check
flag), `campaign` (dashboard-db flag), and, on a **main push** of a digest-only change
to `deploy/k8s/overlays/prod/kustomization.yaml`, it skips the four validate parts.
Everything else always runs. Measured consequences: the docs-only PR #1680 ran the full
run (validate 11.5/11.5/12.9/6.4 min plus an ingestor build-check); the pin PR runs
(for example 43900493340) ran the full run (validate 11.1/10.1/6.2/13.8, 43.1 min wall);
the pin push to main still ran campaign-qualification, both firmware compiles and the
platform checks (about 47 runner-minutes). Per class, the minimal proof:

| class | must still run | can skip |
|---|---|---|
| docs-only (Markdown no test/script/CI names) | precheck, secret-scan, lint, path-impact, buildcheck (ingestor copies `docs/`), dashboard if its flag | validate parts, platform-*, campaign*, firmware-* |
| pin-only (digest/comment lines of the 3 pin files) | precheck, secret-scan, lint, both renders, zero-Secret render, pin-shape tests | the rest |
| firmware-only | full validate (containment-firmware has the native tests, invariants, rule 6, replay diff), firmware compile, firmware-logic | nothing safely in A; campaign/dashboard-db could skip (B) |
| dashboard-only | dashboard, validate (dashboard manifests/tests live there), buildcheck | firmware compile and firmware-logic (A does this) |
| manifests-only | validate rest + manifest tests | firmware compile (A); campaign-qualification (B, needs mapping) |

Skipping without leaving a required context pending: a reusable-workflow caller job
skipped by `if:` reports only a check called `ci` (not `ci / <check>`), so the required
context never appears and the merge blocks. Group A therefore skips only **shard
matrices** (never required) and lets each required context pass in-script as "not
impacted" (the pattern `dashboard.sh` already uses).

**Q4. Sharding.** Existing shards: validate (4 parts), campaign-qualification (4),
campaign (4), firmware compile (2). Balance: validate parts 13.4 / 10.3 / 9.9 / 6.4
(round-robin by list position, not by time); campaign-qualification 8.0 / 7.6 / 7.6 / 4.7
(every n-th file). After #1685 removes the 6.8-minute containment proof and about 70
experiment, twin and planner test files, containment-firmware drops to about 3 minutes
and pure-logic shrinks; the right move is then a timing-balanced split (B1), not more
shards now. Each extra validate shard costs one ci-set slot and 71 s of pip install
until the deps are baked into the job image.

**Q5. Duplicated or dead work.**
- `ci / campaign` ran the 31 dashboard-db files that the campaign-qualification shards
  already run (logs of 43901036326 and 43912143552 list identical files). Measured cost
  when impacted: 19.2 and 37.6 runner-minutes; always 4 extra tools pods. **Fixed in A.**
- `platform-tests` re-runs 16 files that validate already runs (only
  `tests/test_gha_firmware_secretless_compile.py` is unique), on Python 3.12, while
  the images and validate use 3.13. `platform-static` ruff is a subset of validate-rest's
  ruff. firmware-logic re-runs the logic tests and replay invariants of
  containment-firmware. All three are required contexts (C2).
- Retired with #1685 (verified in its diff): the containment proof (6.8 min per run),
  the planner_graph suite and its pip install, the twin compile, about 70 experiment and
  ledger test files, the orchestrator and planner build/build-check profiles. Nothing
  left in A for them; #1685 does it. A merges with #1685 with one trivial conflict
  (modify/delete of `ci/gha/campaign-checks.sh`: keep the delete).
- Orphan tests: `tests/test_gha_build_base_and_buildcheck.py` and
  `tests/test_build_hand_pinned_images.py` are collected by no CI step (B4).
- Gap, not duplication: no CI step asserted zero `kind: Secret` in the prod render
  (validate-rest renders to /dev/null). A adds it to the pins part; B5 adds it to rest.
- buildcheck-image builds only images whose Dockerfile inputs changed (already
  limited). But `ingestor/Dockerfile` copies all of `docs/` and `scripts/`, so every docs
  or script change builds an ingestor (PR build-check and main build) and opens a pin PR
  (C5).

**Q6. After every merge.** Today: a main `ci` run (52 of the last 150 runs were main
pushes), a `build`, and a pin PR whenever an image digest changed (22 of 150 runs were
pin-PR runs). The pin job already opens no PR when no digest changed
(`pin-bump.sh`: "pins already current; no PR"); the pin PRs that look needless come from
the ingestor's `COPY docs/ scripts/` (C5) and from non-reproducible digests (GIT_SHA
build arg). With A, a pin PR's run and the pin push's main run become the light pins
path (about 4 minutes, about 8 runner-minutes). Skipping the main run when the merged
tree was already green is C1 (owner: #1535's 30-main-run acceptance). The pin job lives
in estate-ci (`pin-bump.yml`/`pin-bump.sh`); the build impact and the ingestor COPY
live here.

**Q7. Concurrency.** Already in place: `cancel-in-progress` is true for
`pull_request`, grouped per PR number, so a new push cancels the older run (most of the
30 cancelled PR runs in the sample). Main runs are grouped per commit and never cancel
(#1535: no displaced main runs). Today's hand cancellations were for other reasons
(base not main, freeing runners, folded PRs), not missing concurrency.

**Q8. Slow start.** No flaky failures. Slowness is queueing: every job is a fresh pod
with a fresh checkout and dependency install, and the 5-second aggregates queue on the
busiest set (p90 12-22 min). The esphome set (max 3) queues the second run's compile
(the recovery target started 8 min late in 43912143552). Set-up job and runner start
take about 1 s once a pod is assigned.

**Q9. Must not be weakened** (A keeps all of them on every full run):
device-write gate tests (`test_device_write_gate.py`, validate-rest and platform-tests:
the only code guard between CI and ESP32 writes); migration qualification and ledger
tests (`check_migration_rollback_safety.py`, `test_apply_migrations_runner.py`,
`test_migration_rollback_safety.py`: an edited applied migration fails the ledger at
sync); firmware native tests, invariants and the replay diff (containment-firmware: the
offline proof of control behavior before a flash); zero-Secret render (the AppProject
rejects the whole sync); secret scan (public repository); the hosted-runner ban
(`test_no_hosted_runner_workflows.py`, `ci / lint`: public repo on paid/hosted compute);
rule 6 and rule 7 diff gates (fire-and-forget tunables, stale-schema restarts). The
light classes cannot contain a firmware, schema, migration or code path, so none of
these can be skipped by them.

## 10. Owner decisions C1, C2 and C5

**C1. Skip the main `ci` run for a tree that was already green as a pull request.**
- **Today.** 52 of the last 150 `ci` runs were main pushes. Each is a full run (about
  100 runner-minutes, 13-18 min uncontended) that re-proves a tree the pull request often
  proved already. The branch rule does not require the branch to be up to date, so
  main's tree equals the tested merge commit only when main had not moved before the
  merge.
- **Change.** On a push to main, path-impact looks up the merged pull request's last
  successful `ci` run. If that run's merge commit has the identical tree, every context
  passes as "verified on the pull request"; otherwise the run is full as today.
- **Saves.** Up to about 100 runner-minutes on most main pushes, and frees runners for
  the release trains.
- **Risks.**
  - It weakens #1535's acceptance ("30 consecutive main runs, at least 90 percent
    successful"), because most main runs would no longer exercise the gates.
  - A wrong tree comparison would let an untested tree through. Mitigation: an exact
    tree hash comparison, falling back to the full run.
  - Main runs also catch drift from things outside the tree (job images, estate-ci pins).
- **Recommendation.** Yes, after #1535's 30-run window closes, with the exact-tree rule.
  Keep one nightly full run on main to catch image or toolchain drift.

**C2. Retire the three duplicate required contexts (platform-static, platform-tests, firmware-logic).**
- **What they duplicate.**
  - `platform-tests` runs 17 test files and a verdify_schemas subset; 16 of the files
    already run in validate.
  - `platform-static` runs ruff over a subset of what validate-rest lints.
  - `firmware-logic` runs the logic tests and replay invariants that validate's
    containment-firmware part runs.
  - `platform-tests` runs on Python 3.12, while the images and validate use 3.13, so it
    is the less faithful copy.
- **Change.** Move the one unique file (`tests/test_gha_firmware_secretless_compile.py`)
  into validate. Make the three contexts aliases that aggregate the validate parts, so
  the branch rule is unchanged, or remove them from the branch rule.
- **Saves.** 3 ci-tools pods and about 3.6 runner-minutes per full run, plus three queue
  slots on the busiest set.
- **Risks.**
  - The contexts became required on 2026-11-13 under #1535 (default a). Removing them
    changes that record, and the branch-rule write is the owner's.
  - Coverage risk is nil once the unique file moves.
- **Recommendation.** Keep the context names as aliases of validate. That gets the saving
  with no branch-rule write.

**C5. Narrow the ingestor image's copy of `docs/` and `scripts/`.**
- **Today.** `ingestor/Dockerfile` copies all of `docs/` (for the Iris planner playbook
  and the daily site-content RAG refresh) and all of `scripts/` (for the forecast-action
  engine and embed-corpora). So every docs or scripts merge builds a new ingestor
  candidate, a PR image build-check (about 3 min) and a pin pull request with its own CI
  run. Several pin PRs today were exactly this, and the coordinator closed them as stale.
- **Change.**
